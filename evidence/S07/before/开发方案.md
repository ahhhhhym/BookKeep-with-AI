# AI 辅助记账软件开发方案

版本：1.1（S06起全部移交Codex）｜日期：2026-10-20｜项目目录：`D:\BookKeep with AI`

## 1. 目标、交付边界与分工

开发一款 Windows 10/11 x64、中文界面、本地单用户的桌面记账软件。先提供可靠的手工记账和支出统计，再加入 DeepSeek 截图识别：图片生成候选支出，用户补全、修改并审核后，才进入正式账本。

用户已确认 Windows 桌面版。首版交付可解压运行的 ZIP，用户不需要安装 Node.js、Python 或 DSH。DSH 是开发工具，不是软件的运行依赖。ARM64、手机端、云同步、多人协作、银行自动同步、收入与预算列为后续需求，不混入首版验收。

“自动创建账本”的首版解释：首次启动自动建立“默认账本”；AI 自动整理的是该账本内的待审核支出记录。AI 不擅自新建多个账本或改变账本归属。如将来需要按年度或用途自动分账本，先补充单独需求。

**当前S01～S03文档、S04工程骨架和S05数据/仓储已通过对应阶段接收；S06手工记账已实现并完成自测，S07未开始，G1～G6均未通过。S08另轮验收，本次未重建软件包。历史文档ZIP、S04冒烟ZIP与未来正式软件ZIP分别追溯。**

## 2. 功能和业务口径

### 2.1 基本记账

1. 首次启动创建默认账本；手工新增、编辑、删除支出，删除采用软删除并支持恢复。按日期和分类筛选、按名称搜索。
2. 金额内部用人民币“分”的整数，输入正数，展示统一两位小数；列表可用负号表达支出。避免浮点累计。首版仅人民币，金额允许范围建议 0.01～9,999,999.99 元，超出提示用户。0 元、非法数字和超过两位小数不能静默入账。
3. 一级分组：今天/昨天/几月几日、星期几、当日总支出。跨年记录显示年份。点击日期组可折叠展开，默认展开；按日期倒序排列。
4. 二级记录：名称、分类名称及图标、金额；同日按已知发生时间倒序，时间未知的按创建时间和 ID 稳定排列。不能从导入时间伪造交易时间。
5. 只统计正式、未删除的支出；待审核、拒绝、失败的识别结果不参与任何金额汇总。
6. 时间采用账本时区 Asia/Shanghai。记录区分“日期已知”和“精确到分钟的时间已知”，日期缺失必须补填；只有日期时不能自动补成当前时刻。周一为每周起点。
7. 支持 CSV 导出（UTF-8，正确处理中文和表格公式前缀），完整备份与恢复。备份含数据库、附件、版本清单，默认排除密钥；恢复前备份当前数据并校验文件。首版不要求任意 CSV 导入。

### 2.2 分类和图标

以图二为视觉参考，共 **33 个消费分类**：餐饮、购物、日用、交通、蔬菜、水果、零食、运动、娱乐、通讯、服饰、美容、住房、居家、孩子、长辈、社交、旅行、烟酒、数码、汽车、医疗、书籍、学习、宠物、礼金、礼物、办公、维修、捐赠、彩票、亲友、快递。

“设置”是功能入口，不作为消费分类。额外保留系统分类“其他”，承接用户确认的未分类支出。分类有稳定 ID、中文名称、图标标识、排序与启用状态。首版支持给既有分类改名、换图标和停用，以及新建自定义分类；被引用的分类只能停用或显式迁移，不能删除后使旧记录失联。

图标语义对应参考图，例如餐饮用餐具、交通用公交车、数码用数据线、维修用锤子。采用有许可的本地图标或原创 SVG，保留许可文件；不直接裁切截图作为生产素材。图标旁保留文字，选中态可以使用浅蓝填色。

### 2.3 统计图表

| 视图 | 点和范围 | 点提示框内容 |
|---|---|---|
| 周 | 选定周，周一至周日，共 7 个日点 | 日期、当日总支出、金额最大的前三笔具体支出名称及金额 |
| 月 | 选定自然月，28～31 个日点 | 同上 |
| 年 | 选定自然年，1～12 月，共 12 个月点 | 月份、当月总支出、当月汇总金额最大的三个支出类型及金额 |

提示框将总支出放在上方，前三项放在下方；支持鼠标悬停、键盘聚焦和点击固定。空日期或月份补 0，不跳过，少于三项显示实际数量，没有支出显示“暂无支出”。并列时按金额倒序、随后按发生时间和稳定 ID；分类并列按分类 ID。不能把年度提示框误写成前三笔交易。

提供上一周期、下一周期、返回当前周期及周期选择。未来日期不可选；当前周/月/年仍画完整周期，未来点显示“尚未到来”，不提供已发生的统计明细。

显示周期总支出、日均支出、分类排行榜。历史完整周期的日均为总额÷周期自然日数；当前周期除以从周期开始到今天的自然日数；年视图同样显示“日均支出”并注明分母，包含无消费日。分类比例以当前周期总额为分母，总额为零显示 0%；百分比四舍五入可不严格合计 100%，金额必须相等。

建议验收固定数据：2026-09-08 午餐 18、购买水果 16.26（分类水果）、晚餐 10，当日 44.26；2026-09-09 iPad维修 850（维修）、iPad保护膜 55.54（数码）、午餐 15.50（餐饮），当日 921.04。两天合计 965.30，9 月前三分类为维修 850、数码 55.54、餐饮 43.50；这是独立验收数据，不能套用截图中的 948.41 或分类比例。另加第四笔和多天同类支出，验证 Top3 截断和分类聚合。

### 2.4 AI 识别与审核

流程：选择/拖放图片 → 本地预览、裁剪及遮盖敏感信息 → 用户发起识别 → 上传预处理图片 → 结构化候选 → 字段校验/重复提示 → 用户修正并审核 → 原子入账 → 刷新统计。

首版每张图片一次请求，支持队列批量导入，每批上限 20 张、默认并发 2；单张本地限制 10 MiB、最长边 8192 像素，可配置压缩但不影响文字可读性。支持 JPEG、PNG、WebP；其他格式先明确提示，不直接按扩展名相信内容。尺寸和解码检查在上传前完成。长截图后续可增加分段识别；首版过长/看不清时请用户裁剪，不承诺自动拼接。

- 一张截图可能有多笔交易，返回 candidates 数组；每一候选保留来源图 ID、局部区域/可读原文证据、金额、发生日期和可选时间、购买物/服务名、商户、候选分类、缺失字段、疑点、模型和提示词版本。
- 商品照片没有交易金额或时间时，这些字段必须为空，要求用户补全；商户名不等于购买物，不能把店名自动当作确定的商品。AI 给不出商品名时要求用户输入。
- 实付金额优先；优惠、原价、余额、合计、单项不能重复计入。清单与总计并存时生成一个明确的交易候选并保留明细，不能同时把明细和总计全部入账。
- 退款、转账、收入、支付失败、订单关闭以及状态不明记录只标疑点，默认不作为可确认的支出；首版让用户排除或改为真实支出，不支持以负金额混入退款抵扣。
- 截图文字仅是数据，不能改变系统规则、执行命令或触发自动入账。模型输出进入严格运行时 schema 校验，未知字段和超长文本受限，JSON 格式正确不等于业务正确。
- 模型自报置信度只做提示，不能作为免审依据；字段缺失、高风险或分类不明均高亮。每笔都需人工确认。批量确认必须展示实际条数和总额，并排除有缺失字段或未处理重复疑点的候选。
- 审核页并排显示原图与候选，支持补填、修改、确认、拒绝、稍后处理。必须确认金额、日期、名称、分类、重复疑点。修改和确认保留审计记录。
- 完全相同图片按 SHA-256 提示并默认复用已有识别任务；内容近似按金额+日期+商户/名称提示，不能仅凭相似度删除真实的第二次消费。确认入账使用唯一候选关联和幂等操作，双击/重试/崩溃恢复不能重复记账。
- 加载状态绑定真实请求和持久化进度；默认单次请求 90 秒，最多两次指数退避重试，仅限网络/限流/服务端临时错误。401/403、余额不足和输入错误直接提示处理；取消后到达的响应不得继续提交。重试可能重复计费，用户手动重试前可见提示。
- 无密钥、离线、超时、服务不可用时仍能手工记账和处理已有草稿。应用不将账本全量发送给模型，仅发送本次图片和必要分类字典。

## 3. 技术方案与关键接口

### 3.1 建议架构

采用 Electron + React + TypeScript，构建工具 Vite，图表 ECharts，本地数据库 SQLite（建议 better-sqlite3）。S04已由DSH锁定工程依赖，实际版本见README和锁文件；后续由Codex沿用并在需要变更时重新核对官方支持范围及Electron/SQLite ABI。现有本机证据不等于Windows10/11双系统兼容已通过。

渲染进程负责交互；受限 preload 暴露类型化接口；主进程负责数据库、文件、密钥、AI HTTP 请求和备份。渲染进程关闭 Node 集成、启用 contextIsolation 和 sandbox，IPC 校验发送方与载荷，不暴露任意文件读写或任意 URL 请求。Electron 官方安全建议见文末来源。

本地业务层只允许审核服务将 AI 候选转为正式交易；图表复用同一统计服务。通过 provider 适配器隔离 DeepSeek、mock 和未来可部署模型。首版不需要自建云后端。

运行时使用 `%LOCALAPPDATA%\BookKeepAI` 储存数据库、附件、备份、脱敏日志；ZIP 程序目录只放应用。解压可运行不代表数据跟随程序移动，跨设备请用备份。多个实例对同一数据库加锁；更新前做备份及迁移。Windows 密钥使用系统用户绑定的加密存储（如 Electron safeStorage），加密不可用时仅本次会话保留，不能明文回退；跨设备重新输入密钥。

### 3.2 数据实体与不变量

| 实体 | 核心字段/约束 |
|---|---|
| Ledger | id、name、currency=CNY、timezone、createdAt；首次创建幂等 |
| Category | id、name、iconKey、sortOrder、enabled；默认字典稳定 ID |
| Transaction | id、ledgerId、amountFen 正整数、currency、occurredDate、occurredTime 可空、timePrecision、name、categoryId、merchant 可空、source=manual/ai、sourceCandidateId 可空且唯一、version、createdAt、updatedAt、deletedAt |
| ImageAsset | id、原始/预处理内容哈希、受限附件路径、尺寸、保留策略；无任意外部路径 |
| ImportJob | id、imageAssetId、status、attempt、provider、model、promptVersion、requestId、errorCode、开始/结束时间；不储存密钥 |
| Candidate | id、jobId、结构化字段及 nullable、evidence、missingFields、warnings、reviewState、version、postedTransactionId；可多笔 |
| ReviewEvent | candidateId、action、修改前后差异、时间、关联 transactionId；事件和入账同事务提交 |
| DatasetSample | sampleId、imageAssetId、人工标签、许可/脱敏状态、split、duplicateGroup、schemaVersion、版本及撤回状态；不自动导出真实图片 |
| EvaluationRun | datasetVersion、promptVersion、模型实际返回标识、provider 配置摘要、指标、样本数、时间/用量及失败原因 |

金额小计、日汇总、图表、Top3 均由正式账本同源计算。候选的未知金额允许 null，正式交易不允许 null。修改采用 version 乐观锁，避免过期审核覆盖新修改。

任务状态：queued → processing → completed / failed / cancelled；completed 表示识别完成，不表示入账。

候选状态：pending_review → approved / rejected；approved 候选编辑正式交易走交易编辑流程，不能重复批准。拒绝后要恢复审核需显式操作并保留事件。审核原子事务：重新校验字段/版本/重复处理 → 创建交易 → 关联候选 → 标 approved → 写审计；任何一步失败全部回滚。

### 3.3 IPC 与 provider 契约由 S02 固化

必须定义请求、响应、错误码、版本和可重试性：ledger.ensureDefault；category.list/create/update/disable；transaction.create/update/softDelete/restore/list；statistics.series/topTransactions/topCategories/summary；image.import/prepare/delete；recognition.start/cancel/retry/status；candidate.list/update/approve/reject；settings.ai/readStatus/saveSecret；backup.create/restore；dataset.export/validate；evaluation.run/status。

主进程不向 UI 返回已保存的 API Key；仅返回 configured 状态和必要掩码。设置页用密码框接收用户首次输入，仅在输入/提交期间短暂持有，受限IPC提交后立即清空，不在渲染进程持久化。安全存取和密钥配置入口由S09实现，S15加固；S04先建立受限设置接口骨架，不依赖尚未存在的完整设置页做探针。分页与筛选、统计起止日期采用包含起始不包含结束的范围，按账本本地日期计算。所有新增/审核/重试动作都有幂等约束与明确错误提示。

provider 输出协议至少包括 schemaVersion、candidates、warnings；候选字段 amountFen、occurredDate、occurredTime、timePrecision、name、merchant、categoryId、evidence、missingFields、warnings。字段不确定即 null，分类不明先保留为缺失待用户选择；schema 与模型输出重试不得自动写正式账本。S02 定义完整 schema 和例子，S09 验证接口模式，S10 才实现生产链路。

### 3.4 DeepSeek 接口事实与待验证事项

2026-10-20 查阅官方文档：产品名 DeepSeek V4.1 Flash，对外调用 `model=deepseek-flash`；2026-10-17 更新记录说明该名称指向 V4.1-Flash-1017。官方 Vision 文档确认可输入图片。来源：[更新记录](https://api-docs.deepseek.com/updates/)、[Vision](https://api-docs.deepseek.com/guides/vision/)。

首选 `https://api.deepseek.com/chat/completions`，用 user 消息的图片内容块发送预处理图片的 base64 data URL。JSON 输出支持是另一项能力，仍须业务 schema 校验；视觉+JSON 参数组合由 S09 实测，不推定任意参数组合均可用。[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

文档核实不等于已经使用本项目账户调用成功，也不代表金额/日期准确率已达标。本次不使用用户贴出的密钥做付费调用。开发时由人类在本地设置页配置密钥，用公开/合成无隐私测试图做最小请求，记录请求日期、模型实际标识、图片输入和结构化输出结果、耗时与错误；不能用文本 mock 冒充识图通过。API 别名可能更新，测试记录必须固定日期和提示词/数据版本。

用户提供的真实密钥不写进源代码、文档、提示词、日志、测试夹具或 ZIP；建议开发者更换已在聊天中公开的密钥。应用密钥与 DSH 自身凭证分开管理，不能复制 DSH 的凭证文件进项目。

## 5. 初版训练框架：先积累可验证的数据

### 5.1 能完成什么

API 调用不会自动训练模型，人工审核记录也不会自动改变 DeepSeek 的模型权重。首版实现“样本—标签—纠错—导出—评测—版本对比—训练适配接口”闭环。提示词改进、分类规则和可选少样本提示均属推理层改进，不能描述成参数微调。少样本检索若启用，只用授权脱敏样本，限制数量与发送范围。

未来真正训练/微调需要重新核实目标提供商是否开放对应服务、训练格式、许可和算力/费用。本方案不假定 DeepSeek 托管 API 提供个人可用的微调端点。训练适配器定义 prepare/validate/submit/status/evaluate 的接口；首版未支持 submit 返回明确 unsupported，无自动后台训练、无虚假训练进度。

### 5.2 人类数据进入流程

1. 人类提供截图，登记来源、允许用途、是否包含个人信息，先脱敏。上传模型与加入训练/评测是两项独立同意，默认不加入数据集。
2. 每个样本记录 sampleId、图片哈希、原始预测、人工真值、日期精度、交易状态、候选列表、schemaVersion、标注人和复核状态；看不清的字段标 unknown，不能让标注者猜金额和商品。
3. 覆盖支付详情、订单清单、多人/多笔、商品照片缺时间金额、优惠实付、退款/转账/失败、跨年/日期缺年、模糊/裁剪、重复和恶意指令截图。
4. 首轮建议 50～100 张脱敏图做基线，不代表足以训练。按来源交易/订单/近似图片组去重分组，建议 train/dev/test=70/15/15；小样本报告实际数量和分组不足。锁定 test，不拿它选提示词或作为少样本示例。人类复核真值优先于 AI 预测。
5. 导出为带版本的 JSONL 与图片清单；训练服务若需要不同格式由适配器转换。备份、数据集导出和运行 ZIP 三者分离。提供撤回/删除传播清单；不承诺能收回已主动导出的外部副本。

### 5.3 指标和建议门槛

金额精确到分准确率、日期精确匹配率、购买物可接受率（人工定义同义标准）、分类准确率、缺失字段召回率、交易检出 precision/recall、重复提示 precision/recall、每张图人工修改次数、端到端耗时和 API 用量。分母和 unknown 的处理在 S12 固化，按场景报告样本数，不能只报一个总准确率。

硬门：100% 正式 AI 交易经过用户批准；未审核金额对统计影响为 0；重复批准新增交易为 0；重要字段校验完整；所有固定账本的金额和 Top3 结果正确；无凭证进入交付物。

建议的 AI 体验目标：在有至少 100 张人类复核样本的基线中，对确实可读的支出截图，金额精确匹配≥98%、完整日期≥95%、可判断类别≥90%；未知金额/日期/购买物的缺失提示召回≥99%。这些是待验收目标，不是性能承诺。样本不足或场景覆盖缺失必须公开分母/限制；不达目标先保持实验性并加强审核，不能靠隐藏难例提高指标。

## 6. Agent 切换和开发者操作

### 6.1 从S06继续

1. Codex使用 `D:\BookKeep with AI` 为工作目录，先读AGENTS.md、执行看板、当前步骤任务书（若存在）、handoff/S05/ACCEPTANCE-R2.md、原S05 HANDOFF及相关规格；读取本次职责变更交接 `handoff/RESPONSIBILITY-CODEX-20261020/HANDOFF.md`。无需启动DSH。
2. 保留S01～S05已接收结论及历史实现归属，从S06手工记账继续，沿用真实SQLite仓储/IPC和已锁定依赖。S05-R2接收通过不等于S08 G1通过。
3. 一次只启用一个写入Agent。切换前等待测试/构建结束，记录未提交变更和commit；无法提交时交付diff、文件哈希及未跟踪清单。不得覆盖来源不明的变更。
4. 将 `分步中文提示词.md` 中S06及后续当前步骤代码块完整粘贴给Codex。每次只运行当前步骤；S01～S05提示词保留作历史查阅，不重新执行。缺少输入先读取，确实缺失再向开发者索取。

### 6.2 每一步必须形成的交接包

- 输入：已通过的上一步 HANDOFF、需求/接口/交互文档版本、当前分支和 commit、工作区是否干净。
- 输出：该步具体产物路径、变更文件、执行命令、退出码/结果、证据路径、未执行检查、已知问题、下一步唯一负责人。
- 结论：待验收 / 通过 / 返工 / 阻塞之一；作者的“自测通过”不自动代表单列验收轮通过；同一会话兼任实现与验收须披露。
- 保密：附脱敏日志与样例，不附密钥、用户真实数据库、原始交易截图或 DSH 配置。

模板与状态表见 `交接与验收.md`。建议保存为 `handoff/S04/HANDOFF.md` 等目录；任务书为 `tasks/S04.md`。Codex在每步HANDOFF报告实现自测及未执行项，在单列验收轮记录接收结论后更新 `执行看板.md`。历史DSH交接保留原文，以本次职责变更确定后续负责人。

### 6.3 验收不通过如何返回

Codex 建问题单：编号、严重程度、需求编号、复现前提、操作、期望/实际、证据、环境、候选版本。阻断项包括金额错误、丢数据、未审核入账、重复入账、密钥泄漏、软件无法启动/恢复。Codex先保留失败证据，返回对应实现步骤补必要回归、修复并记录新commit/文件哈希；再在单列验收轮针对修复及受影响链路复验。S17失败进入S18修复子轮，回S17通过后才正式打包。

若接口或业务口径需改变，先由 Codex写变更决策、更新 S01～S03 规格与影响表，再由Codex修改代码和测试；无须为普通实现细节反复等待人类，但涉及新范围、数据上传用途或公开发布时明确通知人类。

## 7. 未来的软件交付内容

应用包建议 `BookKeepAI-0.1.0-win-x64.zip`：可启动 EXE 及完整资源、中文快速上手、版本说明、LICENSE/第三方许可、样例数据入口（默认空账本，演示账本独立）、文件清单。不能仅压缩一个依赖缺失的 EXE，或把源码目录当作软件 ZIP。

另交 `BookKeepAI-0.1.0-source.zip`、构建说明、锁文件、测试/验收报告、迁移说明、`SHA256SUMS.txt`。源码包排除 node_modules、密钥、用户数据与大体量训练样本。应用和源码的版本对应同一 commit。

在干净 Windows 环境验证：解压、首次启动、手工记账、退出重开、图表 hover/键盘、断网、设置本地密钥后的真实图片识别、补全审核、重复批准、CSV 中文、备份/恢复、中文空格路径、缩放与小屏。记录系统版本、构建版本、ZIP哈希和证据。未验证项目明确列出；不得用构建成功推断桌面操作通过。

## 8. 主要风险及处理

| 风险 | 处理 |
|---|---|
| 图片误识别，实付/优惠/合计混淆 | 来源证据、字段空值、总计规则、强制人工审核、分类分场景评测 |
| API名称/参数变化、费用和网络不可用 | provider隔离、S09真实探针、配置版本留痕、手工离线和草稿恢复 |
| 原生 SQLite 打包或 Electron ABI 不兼容 | S04提前打包冒烟，锁版本并针对Windows x64重建原生模块 |
| 私人消费记录和密钥进入代码/ZIP | 本地系统加密、导出同意、打包允许清单、敏感扫描、真实样本隔离 |
| 切换 Agent 丢上下文或互相覆盖 | 同目录、单写入者、固定编号、commit与HANDOFF绑定、返工闭环 |
| 没有真实样本却宣称完成训练 | 明确框架/评测/真实微调三个状态，指标报告分母，暂缺项留待人类补齐 |
