## 2. 目标、首版范围和不做项

目标用户是本地单用户。核心价值是先保证手工账本与统计正确，再通过消费截图降低录入量，由人补全、逐笔审核后入账。默认空账本，不把演示数据写入真实默认账本。

首版交付包括中文 Windows x64 桌面应用、手工支出及分类管理、日期列表、周/月/年统计、截图预处理与识别队列、候选审核、重复提示、CSV 导出、备份恢复，以及有独立同意的数据登记/标注/纠错/导出/校验/划分/评测/版本管理和未来训练适配接口。S04/S05保留DSH历史实现；S06起全部编程及后续工作由Codex完成，见DECISIONS D43。

首版不做：ARM64、macOS/Linux/手机端、云同步、多人协作、银行自动同步、收入、预算、退款负数抵扣、多币种换算、AI 自动正式入账、按年度/用途自动创建多个账本、任意 CSV 导入、长图自动拼接、无人值守训练、提供商未支持的真实微调或假权重。截图中的支出下拉/饼图等符号不自动扩展为收入、预算或额外报表需求；未单列功能须先做范围变更。

可解压运行不等于用户数据跟随 EXE 移动。应用运行不依赖 Node.js、Python 或 DSH；用户数据位于系统用户目录，跨设备用备份且重新配置密钥。最终发布由人类决定。

## 4. 账本、日期、分类和统计的执行口径

### 4.1 时间与列表

账本默认 Asia/Shanghai，今天/昨天以该时区的日历日期比较，不能用“相差24小时”代替。午夜跨日及应用重新获得焦点时应更新相对日期与当前周期。交易必须有有效日期，精确时间可以未知；日期缺年份不猜年份，缺失需用户补填。同日已知时间倒序，未知时间按创建时间及稳定ID保持顺序；混合已知/未知的完整排序及并列方向交S02统一、S03给出固定例子，不用导入时间冒充发生时间。

日期组总额与条目来自同一正式交易集合。搜索/筛选的列表计数与小计范围由S02/S03显式定义，不能出现有过滤而标签仍暗示完整账本的结果。日期选择的未来限制在本需求中指统计浏览；不据此偷偷增加手工日期规则，S02须定义有效交易日期边界。

### 4.2 初始分类全表

按图2自左向右、自上向下：餐饮、购物、日用、交通、蔬菜、水果、零食、运动、娱乐、通讯、服饰、美容、住房、居家、孩子、长辈、社交、旅行、烟酒、数码、汽车、医疗、书籍、学习、宠物、礼金、礼物、办公、维修、捐赠、彩票、亲友、快递。合计33项；另加“其他”共34个初始消费分类。“设置”不计入分类，不能保存为交易分类。

分类不明的AI候选先保留空值并高亮，只有用户明确选择“其他”后才作为其他支出；不能无提示把缺分类自动转成其他并批准。图标可参考餐具/公交/数据线/锤子等语义，不裁切参考图作生产资源。S03定义稳定ID、图标、排序及停用后的可见性；停用不能改变历史金额及关联。

### 4.3 汇总与Top3

范围以账本本地日期计算，起始包含、结束不包含。正式未删除支出金额整数分累计，再做显示。历史周/月/年的日均=周期总额÷完整周期自然日数；当前周期=总额÷从周期首日至今天（含今日）的自然日数。无消费日仍在分母内，年视图也叫“日均支出”，显示分母。分类占比=分类总额÷周期总额；零总额显示0%，占比显示四舍五入可以不合计100%，金额必须相等。日均及比例的显示精度在S02/S03固化，不改变分母。

日点交易按金额倒序，金额相同再按发生时间与稳定ID；月点分类按聚合金额倒序并以分类ID打破并列。S02须补齐未知时间及方向的严格全序。周/月查看某日的前三笔，不等于整个周期只取三笔；年查看某月的前三分类，必须跨日聚合。前三项不能代替当日/当月全量总额。未来点不是“已发生的零消费日”，不得展示已发生明细。

## 5. 主要操作流程

1. 首启：打开解压后的应用→幂等建立空默认账本/初始分类→进入列表；无需密钥也可使用。重启仍是原账本。
2. 手工：新增→填金额、日期、名称和分类（精确时间可空）→校验→保存正式支出→列表及统计更新；修改、软删除、恢复走同一数据源。无效输入保留可修改表单，不产生半条交易。
3. 统计：选择周/月/年及非未来周期→看总额、日均/分母及分类排行→悬停/聚焦/点击点→看日交易Top3或月分类Top3→可回到当前周期。
4. 识别：选择/拖放→本地校验、预览、裁剪/遮盖→用户知情发起上传识图→仅上传预处理图及必要分类→真实任务队列→校验结构→候选（可能多笔），不触发正式统计。
5. 审核：并排看原图/证据→补齐并核实字段和交易状态→处理重复疑点→单笔确认或符合条件的批量确认（先展示条数与总额）→原子入账→刷新正式账本/统计。拒绝不入账，稍后保留待审核；已批准候选不能再次批准，修改走正式交易编辑。
6. 异常恢复：取消/失败保留任务状态与原因→用户处理密钥、网络或图片→按规则重试；取消后迟到响应丢弃，不恢复提交。重启能找回草稿，不能把处理中推定成功或自动批准。
7. 导出恢复：选择正式交易导出CSV；完整备份独立操作→恢复前先备份当前数据→验证备份完整性和版本→成功切换或失败保留当前好数据；密钥跨设备重输。
8. 数据与评测：用户另行同意纳入数据集→登记许可/脱敏/标注/复核/版本→分组划分并锁test→授权导出/运行评测→真实与合成报告分列。撤回传播到本地登记/后续导出清单；不能承诺收回已导出的外部副本。
